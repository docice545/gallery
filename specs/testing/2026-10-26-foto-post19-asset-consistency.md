# FOTO после Build 19: OCR, удаление Android и карта

База: `e2a95e6aeee9d9da8d23ca7643a6a061c61944c3`. Следующий APK не выпускается этим изменением.
Production Build 19 и его Web Live Photo остаются базой отката. Новых API, зависимостей и миграций нет.
Сведения об отсутствующих production UUID и healthy-контейнере предоставлены владельцем; из облака
production, PostgreSQL/Redis и оригиналы не запрашивались и не изменялись.

## Причины и поведение

OCR читал asset до долгого запроса ML, затем безусловно записывал дочерние строки. DELETE между этими
шагами вызывал корректную FK-ошибку. Теперь ML выполняется без блокировки, а короткая транзакция
проверяет и блокирует родителя `FOR UPDATE`, сохраняет OCR/search/completion атомарно. Неактивный,
удалённый или скрытый asset получает `Skipped`. Остальные ошибки продолжают исходный путь обработки;
FK не отключён, новые catch/retry не добавлены. Конкурирующие DELETE и повторные OCR сериализуются.

Thumbnail HTTP 400/404 неоднозначен: общий access gate использует его и при запрете доступа.
Проверка owner-scoped deletion receipt предшествует удалению remote cache. Подтверждённое удаление
транзакционно сохраняет permanent marker и применяет существующий sync-delete. Оригиналы,
MediaStore-очередь, EXIF и GPS не затрагиваются. Старый backfill не возвращает удалённую запись.
Запросы сверяются с текущими аккаунтом, каноническим сервером и разрешённым LAN-маршрутом;
проверки ограничены, объединяются по ID и не имеют фонового цикла повторов. Неоднозначные ошибки
остаются диагностическими, запускается только обычная incremental sync без сброса ACK.
Переиспользование Thumbnail очищает старые пиксели; повтор failed URL разрешён при новой ревизии,
а обычный rerender не создаёт запрос.

Явное локальное удаление раньше обходило проверяемый native-путь через PhotoManager с `typeInt=0`,
а CleanupService терял причину исключения. Теперь используется существующий trash-only delegate
с реальной локальной identity. На API 30+ явная операция без MANAGE_MEDIA запрашивает системное
согласие в активном Activity. Автоматическая очередь по-прежнему требует прежних разрешений и не
показывает неожиданных диалогов. Каждому ID сопоставлены permission/identity/system-result/verification
диагностики без имён файлов и путей. RESULT_OK недостаточен: успех подтверждает MediaStore.
Отмена прекращает следующие пакеты. Повторно использованный ID не подтверждается даже при уже
удалённом другом файле. Ошибка локальной БД после операции не скрывается. Permanent-delete fallback
для Trash отсутствует; существующее явно выбранное окончательное удаление сохраняет семантику.

Оба превью карты содержали константу Hawaii. Начальная точка теперь читается из доступной фотографии
текущей библиотеки с валидным GPS; явная координата маршрута имеет приоритет, отсутствие GPS даёт
нейтральную мировую карту. Права геолокации устройства для этого не запрашиваются.
Исправлены устаревшие async-запросы locale, прерывание после отказа одного слоя и вложение выражений
при повторной смене языка. Геокодер ограничен двумя запросами с общим deadline и одной нативной
операцией. Временный отказ не сохраняется как часовой отрицательный ответ; доступно ручное обновление.

## Границы подтверждения

- Реальная причина отказа шести Samsung MediaStore ID без состояния телефона не установлена.
  Проверены дефекты пути вызова и воспроизводимые сценарии отказа, а не реальные пользовательские медиа.
- Selected-only media permission сохраняет безопасный отказ с причиной: текущая проверка identity
  требует полного разрешения чтения соответствующего типа медиа.
- Без авторизованного deletion receipt нельзя считать произвольный HTTP 400/404 удалением. Такой
  UUID ожидает штатного sync delete event; запрещено удалять asset или оригинал ради исправления UI.
- Русский язык зависит от Android Geocoder и языковых полей/глифов провайдера тайлов. Источник без
  русского имени сохраняет исходное название, без транслитерации. Реальный Samsung и нативная карта
  не проверены эмуляторными/Flutter-тестами.
- Существующий серверный GeoNames DTO не передаёт языковые теги aliases. Надёжный серверный вариант
  требует отдельного изменения: language-tagged имена, параметр locale с исходным fallback и тесты
  сохранения текущего API. Автоматически применять aliases по признаку кириллицы нельзя.
  Этот вариант не реализован и в production не внедрён.

## Безопасная подготовка backend на HP

Проверки окончательного кода: Flutter — **5 285 passed, 1 ранее существовавший skip**;
целевые Android suites — **318 passed**; JVM — **78 passed**; Flutter analyze — **No issues found**.
Server — **6 953 passed, 12 ранее существовавших skip, 1 ранее существовавший expected-fail**;
изолированные PostgreSQL integration/regression — **31 passed**. TypeScript, scoped ESLint/Prettier,
Dart format и server production compilation прошли; postbuild сохранил два migration aliases.

Первый общий Flutter-прогон выявил ошибки новых fixtures/старых ожиданий batching; они исправлены,
полный окончательный прогон прошёл. Первые тяжёлые проверки исчерпали доступную память; повтор
с ограниченным параллелизмом и подходящим Node heap прошёл без отключения тестов или функций.
В stderr Flutter сохраняются ранее встречавшиеся сообщения `Callbacks into the Dart VM ... finalizer`
при освобождении FFI-ресурсов, при успешных тестовых assertions и exit code. Они не подавлялись;
этими проверками нельзя подтверждать отсутствие аналогичной проблемы на физическом устройстве.

Ветка публикуется без открытия PR: существующий `build-mobile.yml` запускает сборку/подпись APK
при `pull_request`. До отдельного решения о выпуске этот workflow не инициируется.

Web-only overlay не доставит OCR-код. После проверки итогового полного SHA владелец может извлечь
и выполнить build-only скрипт; он не переключает checkout Build 19 и не запускает контейнеры:

```bash
cd /mnt/hp-data/foto-build19-source
FOTO_FIX_SHA=REVIEWED_FULL_40_CHARACTER_SHA
git fetch origin refs/heads/codex/foto-post-build19-asset-consistency:refs/remotes/origin/foto-post19-review
git show "${FOTO_FIX_SHA}:deployment/build-foto-post19-backend.sh" > /tmp/build-foto-post19-backend.sh
bash /tmp/build-foto-post19-backend.sh "$FOTO_FIX_SHA" /mnt/hp-data/foto-build19-source
```

Скрипт требует чистый checkout на точной базе, отсутствие build-lock, локальный Docker и существующий
`foto-build19-web:e2a95e6`. Он проверяет неизменность зависимостей, API/SDK, схемы и build scripts,
архивирует только отслеживаемые исходники в новый каталог HP, применяет существующий branding,
собирает только backend и копирует новый `dist` поверх точного существующего runtime.
Manifest API остаётся `5.7.3`; Web, зависимости, CLI, плагины и конфигурация runtime наследуются.
Миграционные compatibility aliases проверяются. Старые теги не заменяются; каждый кандидат имеет
уникальный тег `foto-post19-backend:<12-symbol-SHA>` и provenance. Ошибка preflight — основание
остановиться, а не удалить lock, подменить базу или отключить TLS.
Этот Docker-образ не проверен сборкой на HP в облачной задаче.

## Выпуск и откат — отдельное решение владельца

До разрешения выпуска не собирать/подписывать новый APK. После решения нужны следующий уникальный
versionCode, прежний production-сертификат, проверка package ID и обновления поверх установленного
Build 19. Пароли/keystore не передаются в Codex. Не устанавливать APK автоматически.

Для backend перед будущим deployment сохранить точный image ID текущего `immich_server`, проверить
его Compose project/service/config_files и mounts адресным `docker inspect --format` без вывода Env.
Использовать тот же Compose-проект и только временный image override; основной production Compose,
mounts, env и command не менять. Не выполнять `down`, `prune`, запуск новых PG/Redis/ML-сервисов,
очистку очередей и массовый OCR/reimport. Проверять новый код на отдельных синтетических объектах.
При ошибке вернуть только image сервера к сохранённому Build 19 ID в том же проекте. Файлы схемы
не изменены: DB rollback, очистки таблиц, переиндексация и изменения NAS не требуются и не разрешены.

Приёмка на Samsung после отдельного выпуска: системное согласие accept/cancel, отсутствие MANAGE_MEDIA,
отзыв чтения, частичный отказ, перезапуск ожидающих операций, отсутствие повторных диалогов; исчезновение
подтверждённого удалённого asset и Restore без загрузки локального оригинала; карта холодного старта,
Москва/Химки/Внуково/Белек/Муйне/Немчиновка/Восточное Дегунино/Новая Купавна/Гонолулу, offline fallback
и обновление имён после восстановления сети. Не применять сценарии удаления к реальным оригиналам.
