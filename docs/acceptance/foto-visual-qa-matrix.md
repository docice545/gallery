## Повторение visual captures

После setup/codegen использовать команды из README каждой evidence-папки. Дополнительный comparison board и реальные grouping controls:

```bash
bash docs/acceptance/capture-cloud-visuals.sh "$PWD" /tmp/foto-controls-memory
```

Скрипт создаёт только собственный временный test-файл, вызывает настоящий `flutter test`, сохраняет renders и удаляет этот временный файл. Не изменяет golden baseline. Пустая середина comparison board — специально свободное место небольшой fixture, не доказательство пустот реальной ленты. Offline/horizontal snapshots, напротив, проверяют сам Timeline и реальные decoded fixture pixels.

Дополнительное системное доказательство для V01/V06/V12: [Android AVD online/offline restart](../../specs/testing/foto-build38/offline-emulator/README.md), настоящие просмотренные кадры и source/APK hashes. Подтверждены два cached server images и неизменная область ленты; fast-scroll и local-only сценарии проверены отдельными Flutter tests. Это не Samsung acceptance.

Для аппаратной приёмки заполнить `visualChecks` в [result template](build38-result-template.json): model/OS, artifact SHA, timestamp, capture path/hash, PASS/FAIL и замечание для каждой строки. Снимать только выделенные тестовые фотографии. Дополнительно записать single/batch deletion в timeline/viewer/album, slow network/offline и AI before/after. Сам факт записи без просмотра и оценки не равен PASS.

Общий visual status: **CLOUD_REVIEWED_WITH_LIMITATIONS; DEVICE_REQUIRED**. Полная приёмка требует реального Samsung, iPhone и подтверждения качества, особенно V07/V11. Изменение цветов или golden файла ради формально зелёного отчёта не заменяет исправление дефекта.
